관광공사 소비·방문객은 플랫폼에 회원 로그인해 전체 기간 CSV 를 내려받고 `tools/import_ijto.py` 로 정리했습니다. 소비 파일(59만 줄)은 같은 (달, 관광객구분, 읍면동, 업종)이 파일에 없는 세부 구분으로 여러 줄 나뉘어 있습니다. 줄 수가 두 배로 늘어난 달에도 월 합계(4천억~5천억 원대)가 고르게 이어져, 서로 겹치지 않는 조각으로 보고 더해 48,598줄로 만들었습니다. 합친 뒤 소비금액·이용건수 합계가 원본과 같은지 확인했습니다. 상가 매장 수는 전국 zip 에서 제주 파일만 꺼내 `tools/import_sangga.py` 로 (행정동, 법정동, 표준산업분류)별 매장 수만 남겼습니다(59,101곳). 법정동 이름 74개는 센터 카드의 법정동 이름과 모두 일치합니다.

**현재 시험 상태**: 공개 데이터 5종은 실제 파일로 시험했습니다. 센터 CSV 의 실제 파일로는 시험하지 못해, 명세서의 컬럼과 코드값대로 만든 가상 데이터로 개발·검증했습니다. 다만 '카드 이용 현황(읍면동)_v02'(1-08)는 대회 게시판 답변(2026-11-09)으로 공개된 실제 CSV 머리글(명세서의 파티션 컬럼 pt_year·pt_month 가 없는 14개 컬럼)로 파일을 만들어 자동 식별·적재·지표 계산이 되는지 확인했고 테스트로 고정했습니다. 대회 운영진 답변에 따라 가상 데이터 제출이 가능하며, 실제 센터 데이터는 센터에서 이용자가 넣어 사용합니다. 가상 데이터의 크루즈 실적(2025.6~2026.10)과 입도통계(2026.10)도 난수이며, 실제 자료는 각각 2025년 5월, 2026년 9월까지입니다. 입도통계 가상값은 2025년 같은 달 실제값에 증가율과 난수를 곱해 만들었습니다. 센터에서 실제 CSV 를 처음 넣을 때는 `tools/center_check.py` 로 형식을 점검합니다(파일 식별, 숫자 컬럼, 코드값, 데이터 간 연결, 지표 12종 계산).

## 2. 이용조건과 반출 기준

제주빅데이터센터 데이터 반출 정책(2026.9.1 개정)을 따릅니다.

| 항목 | 기준 | 구현 |
|---|---|---|
| 원본, 발췌 | 반출 불가 | LLM 과 보고서에 원본 행을 넘기지 않음 |
| 단순집계 | 10 미만 수치 불가 | 범주처리, 삭제처리, 역산 방지 구현 (`guard.py`) |
| 응용집계 | 수치 포함 반출 가능 | 모든 지표를 증감률·비율·지수로 제공 |
| 시각화 | 그림파일(PNG, JPG) | 보고서 차트를 PNG 로 제공 |
| 표 파일 | CSV·엑셀 반출 불가 | 표 파일을 만들지 않음 |
| 출처 표기 | "제주빅데이터센터, 데이터셋(이름, 기간)" | 자동 표기. 공개 데이터는 제공처를 그대로 적습니다. 예: "제주관광공사(제주관광빅데이터플랫폼, 원천 BC카드), 제주 지역별 소비(읍면동)(2025.09·2026.09)", "소상공인시장진흥공단(공공데이터포털), 제주 상가 매장 수(읍면동·업종)(2026.09)" |
| 영리 목적 | 제공기관 협의 필요 | 비영리 공공 활용 전제 |

우리 해석으로 정책보다 엄격하게 적용한 부분이 있습니다.

- 금액이 커도 이용자수나 이용건수가 10 미만이면 작은 칸으로 봅니다.
- 응용집계도 근거 이용자(또는 방문 인원)가 10 미만이면 값을 내보내지 않습니다.
- 종량제봉투(반출 가능)와 크루즈 실적·입도통계(공개)도 센터 데이터와 결합한 결과는 응용집계로만 내보냅니다.
- 관광공사 공개 소비도 센터 데이터와 같은 가드를 거칩니다. 이용건수가 10 미만인 칸의 값은 내보내지 않습니다.
- 가게당 관광객 소비는 금액(가게당 몇 원)을 내보내지 않고 비중의 비율로만 냅니다. 매장 수가 공개 자료라 금액에 곱하면 카드 매출 합계가 되살아나기 때문입니다. 매장 수가 10 미만인 동네는 값을 내보내지 않습니다.
- 외식업 POS 는 표본 가게 수가 10 미만인 지역의 값을 내보내지 않습니다. 함께 보는 외국인 음식점 카드 증감률은 근거 이용자가 10 미만이면 따로 비웁니다.

외부 LLM 전송은 운영진 답변에 따라 "반출 기준을 충족한 집계·가공 결과값"으로 제한합니다.

## 3. 전처리와 분석 흐름

1. **식별**: CSV 헤더를 명세서와 대조해 데이터셋을 찾습니다. v01 과 v02 를 구분하고, 컬럼이 다르면 무엇이 다른지 알려줍니다.
2. **적재**: 코드값의 앞자리 0 이 지워지지 않도록 문자열로 읽은 뒤 명세의 타입으로 바꿔 메모리 DB(DuckDB)에 넣습니다. 종량제봉투 용량("50L")처럼 숫자 타입인데 단위가 붙은 값은 문자열로 두고 계산할 때 숫자로 바꿉니다. 월별 파일은 이어 붙이고, 같은 파일은 내용 해시로 걸러냅니다. 공개 데이터는 같은 달이 있으면 새 파일로 바꿉니다.
3. **집계**: 카드의 지역 키는 (권역, 법정동)으로 씁니다. 월평동처럼 시가 달라도 이름이 같은 동이 있기 때문입니다. 유동인구와 종량제봉투는 행정동 키이며, 종량제봉투의 (시, 행정동)은 유동인구의 "제주시 한림읍" 형식으로 맞추고 권역은 유동인구 데이터에서 가져옵니다.
4. **지표 계산**: 전년 같은 달과 비교합니다. 유동인구는 시각별 방문인구를 24 로 나누고 들어 있는 날 수로 나눠 '하루 방문 체류 인원'으로 씁니다. 카드 이용자구분과 유동인구 국적은 중국↔CHN, 일본↔JPN, 동남아↔VNM·THA·MYS·SGP·PHL·IDN·MMR·KHM·LAO·BRN, 기타외국↔그 밖의 국적으로 맞춥니다.
5. **지역 단위 맞춤**: 카드는 법정동, 유동인구는 행정동 단위라 낙수 지수는 두 데이터가 공유하는 7개 권역 단위로 계산합니다. 쓰레기 부담은 행정동·권역·시·전체 단위로 계산합니다.
6. **새 데이터 맞춤**: 카드 시간대(1-14)는 저녁(18~22시)·밤(22시~07시)을 한 묶음으로 봅니다. 시간대가 "18~22시"처럼 시각 범위로 와도 시작 시각으로 가릅니다. POS 금액에 천 단위 쉼표가 있으면 지우고 읽습니다. 외식업 POS(1-19)는 (시, 법정동) 키라 카드 데이터의 (시, 법정동, 권역) 짝으로 권역을 붙이고, 가게당 매출은 총매출액 ÷ 표본 가게 수로 계산합니다. 업종별 매장 수(1-17)는 시 단위라, 업종마다 '제주도민 개인' 매장 비중을 구해 카드 이용금액에 곱한 뒤 더합니다. 입도통계(P-02)는 국적을 카드 이용자구분에 맞춰 묶고(필리핀 등은 '아시아 기타'에 섞여 있어 기타외국, 내국인은 내국인관광객), 제주 전체 값이라 모든 지역에 같은 분모로 씁니다.
7. **관광공사 공개 소비 맞춤**: 센터 카드(1-08)에 그 달이 없으면 관광공사 소비(P-03)를 같은 컬럼 이름의 보기(view)로 바꿔 씁니다. 관광객구분은 도민→제주도민, 내국인 관광객→내국인, 외국인 관광객→외국인으로, 업종은 음식점업→I56, 숙박업→I55, 소매업→G47, 예술스포츠여가업→R91, 기타서비스업→S96 앞자리로 맞춥니다. 권역은 읍면 이름으로 동부·서부를 나누고, '제주시 동지역'은 연동·노형동·외도동·이호동·도두동·용담1·2동·오라동·삼도1·2동을 중부(서), 나머지를 중부(동)로 나눴습니다(우리 기준). 국적 구분이 없어 중국·일본 등 국적별 질문에는 외국인 전체로 보라고 안내하고, 크루즈 기항 효과는 외국인 전체로 계산합니다. 관광공사 소비와 방문객(P-04)은 같은 행정동 이름을 써서 낙수 지수를 권역이 아니라 읍면동 단위로 계산합니다.
8. **가게당 관광객 소비**: 업종을 고르지 않으면 소매(G47)·숙박(I55)·음식점(I56)·여가(R91)만 소비와 매장 수 양쪽에서 같이 셉니다. 매장 수는 센터 카드면 (시, 법정동), 관광공사 소비면 (시, 행정동)으로 붙습니다. 값은 (동네의 관광객 소비 비중) ÷ (동네의 매장 수 비중)이며 1 이 제주 평균입니다.
9. **크루즈 달 구분**: 카드와 크루즈 실적이 함께 있는 달(4개월 이상)을 모아, 중국발 크루즈 관광객 수의 중앙값으로 '많은 달'과 '적은 달'을 나눕니다.
10. **분석 알고리즘**: 분석 알고리즘 3종(`src/golmok/models.py`)은 관광공사 공개 소비(P-03)·방문객(P-04)·크루즈(P-01/P-08)로 이 PC 안에서 계산하며, API 를 부르지 않고 난수를 쓰지 않아 같은 데이터면 같은 결과가 나옵니다.
    - *기대 대비 실제 소비*: 기준 월 직전 36개월의 (읍면동, 달) 소비를 log 소비 = 동네 고정효과 + 1~12월 효과 + b·log 방문객 + 추세 로 최소제곱 회귀해 기준 월을 예측하고, (실제 ÷ 예측 − 1)을 냅니다. 이용건수 10 미만 칸은 학습에서 뺍니다. 잔차 표준편차 σ 로 90% 범위(±1.645σ)를 벗어나면 '뚜렷함'으로 표시하고, 지난 6개월을 한 달씩 미리 예측한 오차(절댓값 중앙값)를 함께 적습니다.
    - *크루즈 효과 보정*: (읍면동, 달) log 소비에서 동네 평균과 달 평균을 번갈아 25번 빼 두 방향 고정효과를 걷어낸 뒤, 중국 크루즈 관광객이 중앙값보다 많은 달과 적은 달의 잔차 평균 차이를 동네마다 구합니다(이중차분). 섬 전체가 같이 움직인 부분은 빠지므로 섬 평균 동네는 0 근처입니다. 달끼리 값이 이어져 있어 '뚜렷함' 문턱은 표준오차의 2.58배로 엄격하게 둡니다.
    - *동네 유형*: 최근 12개월 외국인 소비의 소매·숙박·음식점 비중, 외국인 소비 비중, log(방문 대비 소비), 1년 전 대비 증가율 6가지를 중앙값 기준 표준화하고 ±2 에서 자른 뒤(극단값 한 곳이 혼자 유형이 되지 않게) k-평균(k=4)으로 묶습니다. 초기 중심은 가장 먼 점부터 차례로 고르는 결정적 방식입니다. 묶음 평균에서 가장 두드러진 특징(소매·숙박·음식점 비중, 낮은 방문 대비 소비)을 한 묶음에 하나씩 짝지어 이름을 붙입니다.
11. **반출 가드**: 근거 표본을 검사해 값을 가리고, 근거 컬럼을 제거합니다.
12. **주의 지역**: 화면은 지표마다 문제 쪽(증감·지수는 기준선보다 나쁜 곳, 비중·값은 가장 나쁜 쪽)으로 가장 치우친 곳 3곳을 '주의 지역'으로 강조하고, '주의 지역 종합'에서는 동네마다 문제 쪽에 든 지표 수를 셉니다. 표본이 적은 값은 고르지도 세지도 않습니다. 가드를 통과한 값으로만 계산합니다.
13. **답변·보고서**: 가드를 통과한 값만 LLM 과 보고서에 씁니다.

## 6. 개인정보와 보안

- 쓰는 데이터는 이미 집계된 형태이며 개인 단위 값이 없습니다.
- 사업체명, 사업자번호가 있는 기업 데이터(2-xx)는 쓰지 않습니다.
- 국적은 카드 이용자구분과 유동인구 국적코드의 집계 범주로만 다루며, 특정 국적을 평가하는 지표는 만들지 않습니다.
- API 키는 `.env` 로만 입력하고 제출물에 넣지 않습니다. 제출 파일 제작 도구가 키 형식 문자열을 검사합니다.
- 질문 내용과 데이터를 파일로 저장하지 않습니다.
